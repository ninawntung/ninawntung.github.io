04 · How I work

Running an AI agent team

Claude Code & Codex · 2026

I don't use one chat for everything. I split production into eight specialist AI agents, and each has its own written role profile, skills and permitted tools. From a local dashboard I choose the agent, point it at the client's project folder and an output folder, and it works only within that role. When a task belongs to someone else, it hands off instead of guessing.

That keeps the AI's work predictable enough to run real client jobs, which means checklists, print files and live revisions, not just demos.

01One role, one jobEach agent has a profile and a list of permitted tools. The filing agent can't edit the checklist, and the designer can't refile logos. Handoffs between roles are explicit.
02Project memory, not chat memoryEvery client folder keeps a decision record, a project log and an index of its official files. Agents read these first, so a new session starts from the confirmed wording and the latest master.
03Safe by defaultAgents keep the originals, back up before changing anything, and log each step. Bulk renames come with an undo script, so any change can be traced or reversed.
04I stay the creative directorAgents propose and produce; I own the creative direction, visual review and final release. Publishing and client contact always need my approval.
Usage trackingThe dashboard also records time spent and token usage for each agent, so I can see where the effort goes.
Logs & handoffsEvery run leaves a short log and a handoff note, so the next session reads a summary instead of the whole history.
Consultant & Agent UpgradeOne agent answers questions about past runs. Another maintains the profiles, rules and shared team memory when I ask.
